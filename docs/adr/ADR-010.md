# ADR-010 — pnpm monorepo

**Status:** Accepted
**Date:** 2026-10-03

## Decision
Use pnpm workspaces with packages: `apps/web`, `apps/api`, `packages/schema`,
`packages/resume-engine`, `packages/ui-tokens`.

## Rationale
- Clear package boundaries help agents stay in their lane and avoid accidental cross-app imports.
- Shared types in `packages/schema` prevent duplication and schema drift.
- pnpm is fast, disk-efficient, and has first-class workspace support.
- A single `pnpm check` at the root runs all gates across all packages.

## Rejected alternatives
- **Single package:** package boundaries blur over time; harder to test in isolation; accidental coupling.
- **Separate repos (micro-repos):** too much overhead for a solo project; shared types become painful.

## Revisit when
Never — for a solo project, a monorepo is always the right call.
