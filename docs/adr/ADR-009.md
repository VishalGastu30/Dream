# ADR-009 — AI: Groq via edge proxy, provider-agnostic adapter, full-context

**Status:** Accepted
**Date:** 2026-10-03

## Decision
Use Groq (free plan, no card required) as the AI provider via a provider-agnostic
`LlmProvider` interface in `apps/api`. The full `llm-context.json` (generated from
published public content at build time) goes in every prompt. No vector database.

## Rationale
- Groq free plan requires no payment details — consistent with the ₹0 rule.
- Full-context is simpler and more accurate than RAG at this data size (~50 items, ~20k tokens).
- Provider-agnostic adapter means swapping to another provider is a one-line config change + evals run.
- No vector database = zero additional infrastructure, zero additional vendors.

## Provider interface
```typescript
export interface LlmProvider {
  id: string;
  stream(input: {
    system: string;
    messages: { role: "user" | "assistant"; content: string }[];
    maxTokens: number;
    signal?: AbortSignal;
  }): AsyncIterable<string>;
}
```

## Guardrails
- Input ≤ 500 chars; history ≤ 6 turns; output ≤ ~400 tokens
- Global daily cap enforced before Groq's 429
- Model name read from config — never hard-coded (Groq's model list changes)
- `llm-context.json` contains only published public content

## Rejected alternatives
- **OpenAI API:** pay-per-token, requires a card.
- **RAG + vector database:** extra infrastructure, lower accuracy at small data size.
- **Google AI Studio free tier:** viable Plan B via the adapter; not default to keep it simple.

## Revisit when
Career dataset exceeds the model's context budget. Implement section-based retrieval first
(still no vector DB needed); only add a vector DB if retrieval accuracy degrades.
