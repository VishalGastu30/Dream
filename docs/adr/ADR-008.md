# ADR-008 — Resume: HTML/CSS template + print stylesheet + Playwright PDF in CI

**Status:** Accepted
**Date:** 2026-10-03

## Decision
Resumes are rendered as HTML/CSS pages with a print stylesheet.
Playwright renders each preset → PDF in CI. Custom selections use browser print (client-side).
PDF text is real, selectable text — not images.

## Rationale
- Real selectable text = ATS-friendly (parsers can extract text directly from the PDF).
- One design system for both screen and print — no second layout engine.
- No server needed for custom selections (browser-side, shareable via URL hash).
- Reproducible: same content input → same PDF output → easy to test.
- Custom selections work offline with no API calls.

## ATS rules for Professional mode (🔒)
Single column · standard section headings · fonts embedded · no icons-as-text ·
no tables for layout · no text in images · consistent `Mon YYYY – Mon YYYY` dates ·
links as visible URLs · no critical info in headers/footers ·
file named `Firstname-Lastname-Role.pdf` · plain-text `.txt` always available.

## Rejected alternatives
- **Server-side PDF at request time:** uses compute quota; harder to cache; cold-start latency.
- **react-pdf:** second layout engine to maintain; harder to match the existing design system.
- **DOCX:** not in v1 scope. Phase 9 backlog item — use a client-side library then.

## Revisit when
You need pixel-exact DOCX output for specific job portals. (Phase 9 backlog.)
