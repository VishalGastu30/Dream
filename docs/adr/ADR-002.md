# ADR-002 — Cloudflare for hosting + API + DB

**Status:** Accepted
**Date:** 2026-10-03

## Decision
Use Cloudflare Workers with static assets (or Pages + Functions — verify which Cloudflare
recommends at project start ⚠️) for hosting, a Hono-based edge API, and D1 for dynamic data.

## Rationale
- One vendor, one dashboard, one free tier to monitor — fewer failure points.
- Same-origin API eliminates CORS and cookie complexity.
- Free tier is well-documented and D1 is explicitly "always free".
- Graceful degradation: static site works independently of the API.

## Rejected alternatives
- **Vercel Hobby:** non-commercial use only — a direct risk if the site is used to support
  freelance work, job applications, or any income-adjacent activity (ADR-002).
- **Vercel + Neon + Render:** three vendors, three dashboards, three potential failure points.
  Render free tier has 30–60s cold-start delays — unacceptable for a portfolio.

## Plan B
If Cloudflare free tier becomes unsuitable:
- Static `out/` deploys to GitHub Pages (already set up as a mirror)
- API moves to another edge/serverless host behind the same routes
- This is possible because `apps/web` is a clean static export with no Cloudflare-specific code

## Revisit when
Cloudflare free tier limits change materially or terms become unsuitable.
