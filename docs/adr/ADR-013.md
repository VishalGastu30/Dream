# ADR-013 — No file uploads / object storage in v1

**Status:** Accepted
**Date:** 2026-10-03

## Decision
v1 has no visitor-facing file uploads. Testimonial author photos are added by the
owner in Git. All media files are committed to the repo and tracked in `assets/manifest.yml`.

## Rationale
- Avoids storage services that may require payment details or moderation tooling.
- Eliminates the need to moderate uploaded files (no NSFW content risk).
- Owner-added media is curated, correctly attributed, and size-optimised.
- `check:assets` validates every file automatically in CI.

## Constraints
- Demo clips: ≤ 5 MB each. Images: ≤ 300 KB each.
- All media in `assets/images/<project-id>/` and tracked in `assets/manifest.yml`.

## Rejected alternatives
- **Cloudflare R2:** free tier exists but adds upload handling, validation, and CDN configuration.

## Revisit when
You need visitor uploads (e.g. a portfolio submission feature, file sharing, etc.).
Then: Cloudflare R2 (free tier ⚠️ verify) + upload validation + moderation workflow.
