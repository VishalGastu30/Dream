# ADR-001 — Next.js (App Router) + TypeScript, statically exported

**Status:** Accepted
**Date:** 2026-10-03

## Decision
Use Next.js with the App Router, TypeScript strict mode, and `output: 'export'` (static HTML export).
Dynamic features live in a separate small edge API (`apps/api`).

## Rationale
- Static output is portable, fast, and free to host anywhere.
- Server Components run at build time — content is pre-rendered without runtime compute.
- A persistent canvas in the root layout survives route changes without remounting.
- SEO-friendly: every page is real HTML.

## Rejected alternatives
- **Next.js with SSR on Cloudflare:** hits the free Workers 3 MiB bundle limit (gzip) and adds runtime compute cost.
- **Astro:** excellent static site generator, but persisting a WebGL canvas across client-side navigation requires more custom work than R3F with Next.js App Router.

## Constraints
- `next/image` needs a custom loader for static export (no default image optimisation server). Use `unoptimized: true` in `next.config.ts`.
- Server-side features (auth, API routes) must live in `apps/api`, not `apps/web`.
- `apps/web` must not import from `apps/api` — shared types come from `packages/schema`.

## Revisit when
You need server-rendered personalised content per visitor.
