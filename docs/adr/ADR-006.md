# ADR-006 — React Three Fiber v9 + drei + postprocessing, procedural-first

**Status:** Accepted
**Date:** 2026-10-03

## Decision
Use React Three Fiber v9 (pairs with React 19), `@react-three/drei`, and
`@react-three/postprocessing`. Build ~80% of the experience procedurally
(shaders, instanced geometry, lines, text). Sourced models are the exception.

## Rationale
- R3F removes Three.js boilerplate while staying close to the metal.
- Procedural-first keeps the initial 3D payload well under the 3 MB budget.
- A unified material on all sourced models hides style mismatches between different authors' assets.
- WebGL has the widest device reach vs. WebGPU (which is still not universal).

## Rejected alternatives
- **Raw Three.js:** more boilerplate, harder to integrate with React 19 lifecycle and Suspense.
- **Spline runtime:** heavy (multi-MB), limited customisation, no code-level control.
- **Babylon.js:** excellent but different ecosystem; weaker overlap with the Next.js/React community.

## Revisit when
WebGPU support is universal and the performance wins justify the ecosystem shift.
Three.js already supports WebGPU from r171+ with zero-config imports — experiment on a branch.
