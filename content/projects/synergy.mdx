## Problem

Campus placement processes involve massive amounts of fragmented data spread across students, faculty, and recruiters. Tracking verified skills and managing placement pipelines manually was inefficient and prone to data loss.

## Constraints

- Required handling five distinct user roles with highly asymmetric data access permissions.
- Needed to provide real-time analytics on cohort readiness without bogging down the database.
- Must ensure a unified user experience despite the fragmented underlying data.

## Key decisions

- Built with Next.js and TypeScript to share types across the frontend and the mock/staged API layer, preventing runtime type mismatches.
- Implemented a unified design system using Tailwind CSS to guarantee visual consistency across all five role-specific portals.
- Used mock-data interceptors early in development to parallelize frontend and backend work streams efficiently.
