## Problem

Investors often receive their trade details via fragmented broker emails and encrypted PDFs. Manually tracking these investments is tedious, and cloud-based automated tools pose severe privacy risks by ingesting sensitive financial data.

## Constraints

- Strict privacy requirement: no financial data can leave the user's device.
- Financial documents are notoriously noisy and irregularly formatted.
- The app must remain responsive while running heavy on-device processing.

## Key decisions

- Chose Flutter for cross-platform UI combined with an embedded SQLite/Drift ORM for robust local data persistence.
- Opted for an entirely on-device LLM pipeline to handle semantic text repair, actively choosing privacy over the raw speed of a cloud API.
- Implemented Gmail OAuth strictly on the client side to retrieve and decrypt PDFs locally.

A brief written description of how the system fits together:
- **Data Ingestion:** Client-side OAuth retrieves encrypted broker PDFs.
- **Processing Engine:** Local Python/Dart pipeline decrypts and extracts raw text.
- **AI Repair:** On-device LLM semantically repairs OCR noise.
- **Storage:** Cleaned trade data is reconciled and stored in the local SQLite database via Drift ORM.
